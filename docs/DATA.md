# Data provenance, calculations and limitations

This document describes the current data and calculation pipeline. Exact counts change when the dataset is regenerated; inspect `app/src/main/assets/pace_dataset.json` and its metadata for the current snapshot rather than relying on stale counts in prose.

## Bundled data

The Android app bundles `app/src/main/assets/pace_dataset.json`, generated by `tools/build_dataset.py`. It contains tournament metadata and season readings for two distinct metrics:

1. CPI physical readings from courtspeed.com.
2. Surface Speed values from the calibrated archive calculation (CALC) and published Tennis Abstract (TA) references/fallbacks.

Where CALC and TA overlap, CALC is primary and the TA value is preserved as `publishedSpeed`. Where no eligible CALC exists, TA remains a labelled fallback. TA is a comparison series, not physical ground truth.

## CPI

CPI combines coefficient of friction and coefficient of restitution:

```
CPI = 100(1 − μ) + 150(0.81 − e)
```

Coverage is limited to instrumented show courts and published records. It does not measure every court or every match at an event. Measurement timing, court identity and surface wear matter.

## Surface Speed

For each server side, the calculation combines the server's ace rate and the returner's ace-concession rate using calibrated odds:

```
O = ((p_server / (1-p_server)) × (p_returner / (1-p_returner)))
    / (p_tour / (1-p_tour))
expected_ace_rate = O / (1 + O)
expected_aces = service_points × expected_ace_rate
side_ratio = actual_aces / max(expected_aces, 0.5)
```

The event raw score is the mean of valid server-side ratios. The season normaliser is the mean raw score across eligible events; dividing by it centres the season around 1.00.

Historical ratings use leave-one-tournament-out player profiles and remove the target event from the tour-average anchor. Player rates are surface-qualified, require at least three matches in a bucket, and use a 150-service-point prior toward the corresponding surface tour rate. Qualified clay and hard/grass rates are blended one third to two thirds; pooled returner fallback is used when neither surface qualifies.

Live ratings use the same expected-aces equation and season normalisation, but their baseline has a different coverage policy: current-season profiles, recent prior-season qualified profiles and explicitly tagged low-sample shrunk profiles can be used. A fresh live manifest excludes active events from baseline training. If the matching baseline is unavailable, the app withholds the rating rather than reverting to the old pooled-rate method.

The expected-aces floor of 0.5 protects the actual/expected ratio from very small denominators. It does not exclude a mathematically valid server side from coverage.

## Live match population and parsing

The app discovers active ATP 1000/500/250 events from the ATP current-scores/results pages on-device. It reads singles match links and distinguishes completed archive links from live/in-progress links. Result-card markers identify walkovers and retirements generically, not through tournament-specific ID lists.

- Played completed singles with valid statistics are eligible.
- Retirements with played-set statistics are eligible.
- Walkovers and confirmed no-play matches are excluded.
- Doubles and in-progress matches are excluded.
- Full-match aggregate stats are preferred. When incomplete, valid played-set arrays are summed; malformed or incomplete played sets remain unresolved.
- Unavailable stats remain visible as missing. The app must not invent values.
- Cache entries are intersected with the current draw so stale match IDs do not contribute.

ATP/Infosys CDN access is device-sensitive. Successful CI verifies code and tests, not necessarily live retrieval from a physical handset. Verify coverage on-device.

## Source selection and provenance

| Use | Source | Notes |
|---|---|---|
| Physical CPI | courtspeed.com | Published show-court readings |
| Behavioural reference | Tennis Abstract | Published rolling reference values |
| Historical match stats | Jeff Sackmann ATP archive mirror | Historical tour-level match data |
| Current-season match stats | TennisMyLife ATP CSV | Preferred when available; source metadata and SHA-256 are recorded |
| Live match stats | ATP/Infosys Stats Plus | Runtime read-only requests from Android |

The current-season pipeline validates the TML CSV schema and records URL, fetch timestamp, latest match date, row count, byte count and SHA-256 in a sidecar manifest. A cached TML snapshot is used only after refresh failure and only if its manifest/hash match and it is no older than seven days. Otherwise the selected fallback source is logged. The event audit can be made fail-closed with `--require-source "TennisMyLife ATP Match Database"`; this prevents an archive fallback being mistaken for a TML population report.

TennisMyLife's [published repository terms](https://github.com/Tennismylife/TML-Database) limit use to personal, educational and non-commercial research; the public terms do not authorize raw CSV redistribution/resale and require written permission for commercial use. Do not commit or redistribute its raw CSV. Derived data does not automatically inherit the historical archive's licence; assess each source's terms independently. See [DATA-LICENSES.md](../DATA-LICENSES.md) for the source-by-source terms, including the Tennis Abstract, courtspeed.com and ATP/Infosys distinctions.

## Current audit evidence

The latest completed formula comparison covered 1,289 common event-seasons across 36 seasons (1991–2026), using 5,000 season-stratified paired bootstrap resamples. The calibrated surface-returner variant scored Pearson 0.925, Spearman 0.926 and MAE 0.052 against the Tennis Abstract reference. This is evidence of agreement with that reference, not physical validation.

The latest deep audit found that the 150-point shrinkage configuration improves historical out-of-sample reference agreement over the unshrunk configuration. Its full-pipeline event bootstrap intervals include profile and target-event uncertainty and are wider than conditional match-only intervals.

Montpellier 2026 has CALC 1.60 versus TA 1.49, with CALC ace rate 14.2% versus TA's published 19.8%. The source-required workflow loaded the TennisMyLife ATP Match Database and reconciled 27 event rows: all 27 met the source-stat eligibility rules (54 statistically complete server sides), totalling 545 aces over 3,839 service points (14.1964%). The production leave-one-event-out player profiles could rate 47 of those 54 sides; seven were not rateable because five lacked a server profile, one lacked a returner profile and one lacked both profiles. No side failed the expected-aces calculation after profiles were available. This explains the 54-versus-47 difference in CALC coverage, but it does **not** explain TA's higher 19.8% ace rate or establish which matches TA included. Do not attribute that remaining discrepancy to qualifying scope without evidence. A local event audit is available:

```bash
python3 tools/audit_event_population.py --event Montpellier --season 2026
```

It writes `build/event-population-audit/match-population.csv` and `summary.json`. Add `--require-source "TennisMyLife ATP Match Database"` to fail closed if the loader selects any fallback. The CSV contains derived match-level reconciliation fields only; it does not include the complete raw source CSV. It describes only the source loaded by `compute_speed.py` and cannot establish TA's population. The successful source-required workflow run on PR #2 head `461272379dc3e69a4b444111b022bf0721f340ef` is [run #42469683324](https://github.com/KR1901/court-pace-index/actions/runs/42469683324).

## Independent physical validation

The ace-based metric is behavioural. Independent validation should use ITF Court Pace Rating (CPR) or properly sourced CPI readings, with event/season/court identity, measurement date, source, surface construction, temperature, humidity, altitude and ball model where available.

Use event-cluster bootstrap intervals, surface-stratified analysis, within-surface association and held-out events/seasons. Do not treat several courts from one tournament as independent events. Do not infer missing environmental or court-specific values.

See [PHYSICAL_VALIDATION.md](PHYSICAL_VALIDATION.md) for the schema and validation protocol.
